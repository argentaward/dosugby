# Правила чистоты кода (Code Rules)

Эти правила обязательны для всех изменений в репозитории. Большая часть правил проверяется **автоматически** линтерами, тайпчекерами и архитектурными контрактами.

---

## 1. Автоматические проверки (Quality Gates)

| Проверка | Backend (`backend/`) | Frontend (`frontend/`) |
| :--- | :--- | :--- |
| **Форматирование** | `uv run ruff format --check .` | `npm run format:check` (Prettier) |
| **Линтер** | `uv run ruff check .` | `npm run lint` (ESLint, `--max-warnings 0`) |
| **Типизация** | `uv run mypy` (`--strict`, запрет `Any`) | `npm run typecheck` (`strict: true`, запрет `any`) |
| **Архитектура** | `uv run lint-imports` (слои и модули) | `eslint-plugin-boundaries` (слои FSD) |
| **Тесты** | `uv run pytest --cov` (покрытие ≥ 80%) | `npm run test` (Vitest) |

Ни одна задача не считается завершённой, пока все команды выше не проходят без ошибок.

---

## 2. Правила Backend (Python / FastAPI)

1. **Разделение слоёв:**
   - В `router.py` **запрещены** прямые запросы к БД (`select`, `AsyncSession`) и сложная ветвящаяся логика.
   - В `service.py` **запрещён** импорт `HTTPException` — используйте доменные ошибки из `app.core.errors` (`NotFoundError`, `ValidationError`).
   - В `repository.py` живут только запросы к базе данных.
   - В `recommendations/scoring.py` — только чистые функции без БД и HTTP.
2. **Контракты API:**
   - Любой эндпоинт возвращает **только Pydantic-схему** (`schemas.py`), никогда ORM-модель напрямую.
3. **База данных и переносимость SQLite → PostgreSQL:**
   - Не используйте SQLite-специфичный SQL.
   - Любое изменение `models.py` сопровождается миграцией Alembic (`uv run alembic revision --autogenerate -m "..."`).
   - В асинхронных запросах связанные коллекции загружаются явно через `selectinload()`.
4. **Безопасность и чистота:**
   - Никаких `print()` в коде приложения (правило `T20` в Ruff).
   - Никакого закомментированного кода (правило `ERA` в Ruff).
   - Секреты передаются только через `.env` и `app.core.config.Settings`.

---

## 3. Правила Frontend (React / TypeScript)

1. **Границы слоёв FSD:**
   - Импортировать можно только со слоёв ниже: `app → pages → widgets → features → entities → shared`.
   - Снаружи обращаться к слайсу только через его публичный `index.ts`.
2. **Разделение ответственности:**
   - В `.tsx`-файлах экспортируются только React-компоненты. Хуки, сторы и утилиты живут в `.ts`-файлах и реэкспортируются через `index.ts`.
   - Запросы к серверу — только через **TanStack Query** (`useQuery`, `useMutation`), никаких `useEffect + fetch`.
   - Клиентское состояние квиза — в **Zustand** (`features/quiz`) с синхронизацией в URL-параметры.
3. **Типизация API:**
   - Запрещено писать интерфейсы ответов бэкенда вручную. После изменения API бэкенда обновите `src/shared/api/schema.gen.ts` (`npm run api:gen`).
4. **Чистота:**
   - Запрещены `any` и `console.log`.
   - Верстка Mobile-first (начиная с ширины экрана 360px).

---

## 4. Ограничения на размер и сложность

- **Функция:** не более ~40 строк, не более 6 аргументов, не более 10 ветвлений (проверяется Ruff Pylint).
- **Файл:** не более ~300 строк. Если файл разрастается — выделите подмодуль.
- **Имена:** понятные бизнес-термины (`audience`, `vibe`, `price_level`, `ScenarioStep`) вместо абстрактных `data`, `item`, `info`, `helper`.
